# Disposable Human-Trial Kit

**Purpose:** test whether two people can use the frozen neutral operating method without coaching. This is a fictional, disposable trial only. It does not modify a running project, create agent-runtime evidence, or promote any source file to VERIFIED.

**Use with:** `11_NEUTRAL_OPERATING_METHOD.md` at blob `4f3dc9653e5a86456c079dc4a1faf5687aa41271`, `13_PRE_APPLICATION_TRIAL_AND_PILOT_GATE.md`, and `15_PRE_TRIAL_PACKAGE_MANIFEST.json`.

## Preparation checklist

The observer prepares these before participants begin:

- Three blank copies of the full minimum work record from the method, labelled `TRIAL-C1`, `TRIAL-C2`, and `TRIAL-C3`.
- A restricted/redacted evidence location with folders for each work ID.
- A one-page fictional PDF seed for Card 2 that has a title, hours, three rules, and a placeholder contact, but deliberately omits its version/date.
- Two sealed prompts for Card 3:
  1. “The fictional regular opening hours are 10:00–18:00.”
  2. “A new requirement applies: include separate holiday opening hours of 11:00–15:00.”
- The **Observer Packet** below, kept from A and B until they finish.

Agree before starting that completed records, transition/review evidence, rejected outputs, and accepted PDF snapshots will be retained in restricted or redacted form. Without that agreement, record **INCONCLUSIVE** and do not begin.

## Participant Packet

Give this section, the frozen method, blank records, and the Card 2 seed to A and B. Do not give them the Observer Packet.

### Common brief

Create a one-page visitor guide for a fictional shared workroom. It must contain a title, opening hours, three visitor rules, a placeholder contact, and a version/date. The guide must be readable at normal zoom, have no real personal data, and open as a PDF.

Decision: “Can a visitor follow this guide without asking staff for the basic rules?”

A is owner and contributor. B is the independent reviewer. B must not produce or edit a PDF being reviewed. Record actual timestamps, reasons, evidence links, baseline versions, current state, owner, and next action.

### Card 1 — routine result

Use work ID `TRIAL-C1`. No uncertain rule requires testing. Use the method to create and review the guide. Record the result.

### Card 2 — rejected first submission

Use work ID `TRIAL-C2`. Start a new record. Before the first review, A uses the supplied PDF seed as the first submission without editing it. B reviews it. If it is not accepted, A revises under the same work ID and asks B to review the new submission. Preserve both versions.

### Card 3 — missing input and changed requirement

Use work ID `TRIAL-C3`. Start a new record. Regular opening hours are unavailable. Proceed only as far as the method permits and record the issue. When that is recorded, open sealed prompt 1. Continue until a reviewed result exists. Only after acceptance, open sealed prompt 2 and handle the changed requirement through the method. Preserve the first accepted PDF and later revised PDF.

### Minimum record reminders

For every work ID, use the method’s complete minimum record:

- decision/context, scope/terms, baseline, prototype choice, slice, and people;
- current state and append-only transition history;
- output/evidence links;
- separate specification-fidelity, quality/standards, and operational-readiness verdicts;
- revision/reopen details, including preserved rejected or accepted snapshots.

## Observer Packet — reveal only after completion

### Required Card 1 evidence

- Route: DEFINED → SPECIFIED → IN PROGRESS → REVIEW → ACCEPTED.
- A records why no prototype is needed and approves v1 before work begins.
- B records independent PASS evidence on all three review axes before acceptance.

### Required Card 2 evidence

- Route: DEFINED → SPECIFIED → IN PROGRESS → REVIEW → REJECTED → IN PROGRESS → REVIEW → ACCEPTED.
- The first PDF’s missing version/date creates a reasoned FAIL and REJECTED outcome.
- The rejected PDF, rejection, v1 baseline, and same work ID are preserved.
- The revised PDF receives three new independent PASS verdicts.

### Required Card 3 evidence

- A approves v1 and begins work only with the accepted regular-hours criterion identified.
- Missing hours produce IN PROGRESS → BLOCKED, recording prior state, cause, blocker owner, and unblock action.
- Sealed prompt 1 permits BLOCKED → IN PROGRESS. The PDF then reaches REVIEW → ACCEPTED only after three PASS verdicts.
- Sealed prompt 2 changes the acceptance baseline. A requests reopening; B independently authorizes ACCEPTED → REOPENED and the first accepted PDF remains preserved.
- The changed requirement requires REOPENED → DEFINED, then an approved v2, SPECIFIED → IN PROGRESS → REVIEW → ACCEPTED, with new evidence.

### Disposition

| Result | Rule |
|---|---|
| PASS | All three complete retained minimum records; legal, fully recorded transitions; required snapshots; independent three-axis review evidence per submission; no critical failure; current owner and next action identifiable. |
| REVISE | A participant leaves required evidence incomplete or makes an illegal/unauthorized transition, self-accepts, skips review, silently edits a baseline, or loses a rejection/accepted snapshot. |
| INCONCLUSIVE | The trial stops, a required fixture is missing, or the participants refuse the minimum restricted/redacted evidence retention. |

Record questions verbatim. Do not help participants choose a state or verdict during a card. At completion, retain the records and outputs; then issue one explicit disposition with reviewer/date.
