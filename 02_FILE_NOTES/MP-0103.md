## Observations
- Good tests are integration-style through public interfaces, behavior-focused, refactor-resistant, and have one logical assertion.
- Bad tests couple to internals, call counts/order, private methods, or side-channel verification.
- Tautological expected values are forbidden; expected values should come from independent known literals/spec examples.
