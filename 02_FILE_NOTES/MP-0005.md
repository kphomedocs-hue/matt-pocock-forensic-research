## Source facts

- Every promoted skill (`engineering/`, `productivity/`) must have a human-facing docs page mirrored under `docs/<bucket>/<skill>.md`; non-promoted buckets must not.
- Docs pages are explicitly not copies of `SKILL.md`; collectively they function as a distributed router for humans.
- Behavioral changes, renames, promotions/demotions, and bucket moves require docs re-sync.
- Published docs use absolute links; no H1; fixed frame includes `What it does`, `When to reach for it`, and `Where it fits`.
- Docs pages must not include install commands; install UI is supplied by the publishing site and canonical wording belongs in `.agents/install-block.md`.
- Pages should prioritize observed user questions from the wiki/issues/changelog over invented FAQs.
- `It's working if` signals must be observable without opening `SKILL.md`.
- Docs should explain why/orientation, not reproduce runbook process.
- First-use AI Coding Dictionary terms should use and link the canonical dictionary terminology.
- Multi-way branches must be rendered as a table or list rather than prose.
- Done criteria require absolute links to resolve, invocation mode/trigger boundary to be stated, and docs to retain the template order.
